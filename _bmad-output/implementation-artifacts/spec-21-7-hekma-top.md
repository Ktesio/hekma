## Intent

**Problem:** FR-57's live view does not exist. `hekma ps` is a one-shot read; nothing shows tokens per second, burn rate or budget left as they move, and nothing acts on a Run from a listing. `hekma agent logs --follow` streams output only by opening the local state directory — the Control API has no output route, AD-20 forbids raw agent output on it "unless explicitly enabled", and that switch (what enables it, who may use it) is **not yet recorded in AD-20** — the story's own readiness condition, unmet at spec time. The CLI's host client speaks only to the local auto-started host, so an Operator cannot watch a remote Service Host at all. And the seam 21-5 built for exactly this — `/v0/events` with `id:` frames, a server-side `selector` and `Last-Event-ID` resume — has no consumer.

**Approach:** One command, `hekma top`, reading only through the Control API (FR-57's letter): a hybrid feed — subscribe to `/v0/events?selector=` with `Last-Event-ID` resume (events trigger a refresh, debounced to ≤ 500 ms) plus a 1 s tick that re-reads `GET /v0/runs` — so any committed Run-visible change paints within 2 s. Rows are 21-5's `RunSummary` pages (exception-first by default, `--all`; `--selector`; cursor paging with `]`/`[`); tokens/s and burn rate are client-side deltas over consecutive refreshes (subtree tokens, est. micros; an honest `—` on first paint, on Runs with no usage, and after a degraded gap > 10 s — never an averaged fiction), budget left from the resolved `budget` block (source-suffixed, `· cum` on process-owning rows). Hotkeys act on the selected row through the existing per-Run Control API verbs — pause, resume, hold, release, stop (a `y/N` second confirm), raise a limit (a value prompt; 21-6's re-arm and un-fence ride it) and attach — each surfacing exactly what its CLI verb surfaces (per-Run results, qualifier notes, typed refusals naming the depth or Metering Source) in a message line, never silently. Attach suspends the view and streams the Run's output through a new `GET /v0/runs/{id}/output` route — operator bearer only, off by default, enabled by `hekma serve --allow-raw-output` (the switch AD-20 must record; Ask First O1, BLOCKING). Local target: the 21-4 discovery + auto-start (top reads and writes through the host, unlike `ps`). Remote target: `--host <url>` + `--bearer-secret <name>` through the resolver, TLS beyond loopback (refused client-side otherwise, mirroring FR-41), over the ureq/rustls stack already in-tree. A Hub target stays out (AD-24 reserved).

**Acceptance Criteria:**
- Given a state dir with two supervised Runs (one healthy, one with a latched `block` breach), a held `wire` Run and an ended clean Run, when `hekma top` starts on a terminal, then within the refresh bound the view lists the breached Run and the held Run (the held row carries its held-call count and oldest age once 23-4's producer exists), the healthy Run is counted not listed, the ended Run appears only under `x` (the all view) inside the window, and every row shows RUN, CONTROL (the depth, `supervised (no wire)` rendered whole), STATUS, ANOMALIES, TOK/S, BURN (est.), BUDGET LEFT — `—` where a figure does not exist, never a fabricated `0`.
- Given the view is live and a Run's status changes (an Operator pause committed elsewhere), then the change is committed to the store and painted by `top` within 2 s (the SSE-triggered refresh debounced ≤ 500 ms plus the re-list; the 1 s tick catching a missed event), with the header showing the refresh age and `live`.
- Given a fresh start (no prior refresh), then TOK/S and BURN read `—` on the first paint and take values from the second refresh on; given the feed loses the host for 30 s (the host stopped), then the view keeps the last rows, the header reads `degraded` with the refresh age and the retry attempt, the rows do not pretend to be fresh, and on recovery the stream resumes with `Last-Event-ID` (or from the tail with one surfaced gap note after a typed `409`) and rates read `—` for one refresh (the gap exceeds the 10 s clamp) before recovering.
- Given the Control API is unreachable at start (no host and auto-start fails, or a remote `--host` that refuses), then `top` exits `1` with the typed message naming the target and the remediation — it never renders an empty table as if it were an empty Fleet.
- Given `--selector team=core` (typed at `/` or on the command line), then only Runs carrying every term (bound or caller) appear, the header names the selector, an invalid selector exits `2` before any connection is made, and a selector matching more Runs than one page still pages (`]`/`[` over the listing cursor; no read loads the whole set — the 21-5 machinery unchanged).
- Given `--ps-seed`-shaped scale (10k Runs, the CI seed), then the first exception page renders within the 2 s bound (the read is `ps`'s: p99 ≪ 1 s; the render is O(page)) and paging a selector-filtered page does the same; the counts line always shows listed/healthy and the page index.
- Given `p` on a selected supervised Run, then the pause goes through the same per-Run Control API verb `hekma agent pause` uses, the row's STATUS becomes `held` within the refresh bound, and the message line carries exactly the qualifier the CLI verb prints (a best-effort note, or the 23-4 wire-hold qualifier on a Run whose adapter declares pause `unsupported` with a wire path — never a native-pause claim); given `p` on an `observed` Run, then the message line shows the typed refusal naming the depth and nothing changes.
- Given `h` then `l` on a `wire` Run, then hold sets (`held` + held count) and release clears it — each through 23-4's per-Run routes, each confirming as `hekma hold`/`hekma release` do (a single-Run act: no prompt beyond the footer's key legend; per-Run results in the message line).
- Given `s` on any Run, then a confirm bar asks `Stop <run>? This ends the Run. [y/N]`, `y` (or `Y`) alone acts — any other key cancels with no change — and the act's result and qualifiers land in the message line exactly as `hekma stop`'s do (at wire depth: the qualified reject, the Run ends).
- Given `b` on a Run with a latched `block`, then the prompt shows the current resolved limits with their sources, a entered value commits through the limits route (`PATCH /v0/runs/{id}/limits`), a RAISE re-arms the latch and clears the matching fence reasons (21-6's rule) — the row's ANOMALIES cell drops `breach[block]` within the refresh bound and the message line names the direction (`raised`/`lowered`); a Caller-class credential is never presented by `top` (operator bearer only).
- Given `a` on a supervised Run against a host started with `--allow-raw-output`, then the view suspends, the Run's attributed output lines stream (raw fallback lines flagged once per attach when the host holds no live capture, re-checked every poll), `q`/Ctrl-C returns to the view with it intact, and no event is written (attach is a read); given the switch is off, then the message line shows `raw output is not enabled on this host` naming `--allow-raw-output` and nothing streams; given `a` on an `observed`/`wire`/`announced` Run or a child Run, then the typed refusal names the depth (FR-49's attach row: fails fast below `supervised`).
- Given a remote target `--host https://host:18499 --bearer-secret ops`, then `top` resolves the secret through the resolver, connects over TLS, and every column, hotkey and state behaves as locally; given `--host http://<non-loopback>`, then `top` exits `2` at startup with the FR-41 remediation (TLS beyond loopback); given `--host` with no resolvable secret, then a typed startup refusal names the secret.
- Given the terminal is resized (narrower, wider, shorter), then on the next refresh (≤ 1 s) the table reflows to the new width (the ps width discipline: `COLUMNS` else the terminal else 80, clamped 40–132; `…` truncation; a column never narrower than its header), the row count fits the new height, and the selection stays on the same Run when it remains on the page.
- Given `NO_COLOR=1` (or `TERM=dumb`), then the view renders without escapes and every meaning survives: exception rows carry a leading `!`, statuses and depths read as words, and no signal is color-only.
- Given stdin or stdout is not a terminal, then `top` exits `2` with `hekma top needs a terminal — use hekma ps for a one-shot listing`, and `--json` still works (a one-shot snapshot document, exit classes per the frozen table, no TUI, no keys read).
- Given an empty state dir (or a selector matching nothing), then the view shows the empty note (`no Runs need attention — N healthy · change the view with x, the filter with /`), creates nothing, and — local target — keeps the auto-started host per the 21-4 lifetime rules.
- Given handoff: fmt, clippy `-D warnings`, the workspace tests, `check_docs.py` (+ `--self-test`), `test_automation.py` pass; changed-line coverage ≥ 95%; one independent review pass done; **the `--allow-raw-output` route does not merge before the AD-20 switch is recorded (O1) and Islam has looked at rendered states of every screen (the visual-design gate)**.

## Design Notes

- **The readiness condition, checked.** The story says the raw-output switch and its authority must be recorded in AD-20 before this story starts. **It is not**: AD-20's Rule carries only "no secret reveal and no raw agent output unless explicitly enabled" (line 199) and the 2026-10-30 amendments list Handoff Mode, TLS, the credential resolver and Run/Policy resources — no switch, no authority. This spec therefore proposes the switch (below) as Ask First **O1, BLOCKING**: Islam records it in AD-20 (AI-58 draft-then-ratify — a spine edit is his, never this spec's), and the route does not merge until it is recorded. Proposal: `hekma serve --allow-raw-output` (default **off**), operator/Host bearer only (the AD-20 matrix's first row — never a Run Key, refresh, announce or proxy-access credential), loopback default with TLS+bearer beyond loopback, and the typed refusal `403 raw-output-disabled` when off. Raw agent output is content the agent wrote (prompts, paths, possibly printed secrets — the review's T6.2 posture: the agent writes `output.log`, Hekma only relays it); that is exactly why AD-20 gates it and why the default is off.
- **The security review's silence, honestly.** The 2026-11 review scopes key custody; it says nothing about raw output, attach or terminal access (its §12 related findings do not cover them). The spec does not pretend it does: it carries its own threat notes (the switch, operator-only authority, TLS beyond loopback, no content in any other payload, the message line never echoing a secret the route returned) and the build's independent pass is briefed with them. If Islam wants the review extended before the route ships, that is his O1 ruling to make.
- **One read path, two triggers.** FR-57's "refreshing within 2 seconds" is `[ASSUMPTION]`-tagged in the PRD (§14 #22); the spec binds it as a real target with a composition that cannot miss it: a committed Run-visible event (status, Anomalies, labels, limits, usage, disposition) fires on `/v0/events` within the writer's commit, the feed debounces bursts ≤ 500 ms, the re-list is `ps`'s indexed read (p99 ≪ 1 s at the CI seed — measured 6.08 ms), and the 1 s tick backstops a lost frame. The bound is asserted in one live test; the NFR-4 10k/100k/1M ladder stays 24.4's. `lagged`, `filter-error` and `replay-error` frames (21-5's honesty markers) each surface as a note and force a refresh — a gap is named, never averaged over.
- **Rates are client-side deltas, by construction.** `RunUsage` carries cumulative subtree totals; there is no server-side rate. TOK/S = Δ(subtree tokens)/Δt; BURN = Δ(est. cost micros)/Δt shown as est. $/h (AD-8: the header carries the `est.` qualifier; a reconciled future figure will label itself). The window is the elapsed time between the two refreshes that produced the delta, clamped to [1 s, 10 s]: below 1 s the delta is noise, above 10 s it is stale — both show `—` for one refresh rather than a fiction. A degraded gap resets the pair. First paint: `—` (AI-18's honest absence, the Fleet cell precedent).
- **The columns.** `RUN` (instance name on process-owning rows, else the run id — the ps rule), `CONTROL` (the depth string, whole), `STATUS` (stored status words), `ANOMALIES` (`breach[block],failed`, held count + oldest age once 23-4 ships, else `—`), `TOK/S`, `BURN (est.)`, `BUDGET LEFT` (per-run tokens + est. dollars remaining, `policy:<name>`-suffixed when Policy-sourced, `· cum N tok` on process-owning rows with a cumulative ceiling; absent, not zero, when unset — the 21-5 discipline). Width and truncation follow the ps rule so the two surfaces never disagree about a cell.
- **Hotkeys confirm as their CLI verb does — because they ARE their CLI verb.** Each key issues the same per-Run Control API call the named command issues and renders the same per-Run result, qualifier note or typed refusal into the message line (stderr's equivalent here — surfaced, not silent). Single-Run acts carry no extra prompt (the CLI's own rule: only multi-Run sets confirm), with two deliberate exceptions: `s` (stop) always asks `y/N` — a hotkey is one keystroke from ending a Run — and `b` inherently prompts for a value. A key on a row whose depth refuses it shows that refusal (naming the depth or the Metering Source) and moves on; it never greys the key out by guessing (the cell answer is the verb's, at act time). Resume (`u`) and release (`l`) ship beside the story's five because a hold with no key to undo it is a trap (23-4's deferred-work entry expects held Runs in these hotkeys), and `p` on a `held` supervised Run is offered as `u` in the footer legend.
- **Local versus remote.** FR-57 says the view "reads through the Control API, so it can point at a remote Service Host or Hub". Local: the 21-4 discovery, and — unlike `ps` — top **auto-starts** the host, because its read path (SSE, the listing route, the output route) and its hotkeys are host surfaces; this is the FR-41 rule applied to a surface that needs a host, not a new one. Remote: `--host <url>` + `--bearer-secret <name>`; the secret resolves through the engine's composite resolver (env, then the state-dir secrets file) so no token ever sits in argv or a shell history; `http://` beyond loopback is refused at startup client-side, mirroring FR-41's server-side refusal; TLS rides the ureq/rustls stack already in-tree (no dependency change). The Hub half of FR-57's sentence is **not built**: AD-24 is reserved and its rule is explicit that no story builds Hub behaviour until it is drafted — the header's host label is a single endpoint, and a Hub target is a deferred trigger.
- **The output route and the 21-4 deferral, closed host-side.** `logs --follow`'s raw-fallback gap (it decides once, at start, whether to stream the raw `agent.log` fallback, so a host that starts or stops mid-follow double-reports or stalls) does not exist on the route by construction: the HOST reads its own engine every poll, re-checking the live capture each time (the cheap status read the deferral names), so a capture appearing or vanishing switches the fallback on the next poll with the one-time qualifier flag. `top`'s attach polls the route on the same tick discipline (≤ 500 ms debounce, 1 s backstop). The route returns the engine's `LogLine` values verbatim — timestamped, attributed — plus the cursor; it never returns a secret the masking rules would hide elsewhere, and it is versioned as part of the Control API (`0.x`, additive).
- **Terminal handling, resize, no-color.** Zero new dependencies under O2's recommendation: the in-tree `console` crate (0.16, already a dependency) provides raw single-key reads, terminal size, cursor control and color with `NO_COLOR`/non-TTY detection. The loop is an input thread plus the feed's tick channel — no blocking read can stall a refresh, and no stdin read happens before the TTY check (the Windows-safe rule). Size is re-read every refresh (≤ 1 s), so a resize lands within one tick; below three usable rows the view shows the header, one row and a note rather than an empty artifact. Color is never the only signal: exception rows carry `!`, and the no-color renders are golden-tested. The visual design itself (layout, density, the exact chrome) is an owner-look gate: the build report carries rendered captures of every state — empty, loading, live, degraded, each confirm, attach — for Islam before merge (Ask First O2).
- **The Naming row, and top's deviation.** The spine's naming row lists `hekma top` among the verbs that "all take `--selector`, `--limit`, `--cursor`, `--json`, `--dry-run`, `--yes`". Top takes `--selector`, `--limit` and `--json`; it does not take `--cursor` (paging is `]`/`[` in-view), `--dry-run` or `--yes` (it is a watch surface whose acts are single-Run and carry their own confirms; there is no set to resolve). The deviation is recorded here and in Ask First 2; if the owner wants literal flag parity, `--yes`/`--dry-run` would suppress (not add) the stop confirm and the `b` prompt — offered as the alternative.
- **Exit codes** map into the frozen table: `0` a normal quit (however long the session), `1` a start-time host/store failure, `2` usage (invalid selector, non-TTY without `--json`, a refused non-TLS remote target); hotkey refusals and per-Run failures never change the exit code — they are message lines (the session continues; the operator is mid-watch).
- **Version and schema.** No engine change, no schema step, no new `EngineEvent`: the engine's log-read facade, the listing and the verb routes exist; the host gains one route and one option; the CLI gains two modules and a command. hekma-engine stays 0.12.0 (the cycle rule); hekma-host's route is additive Control-API `0.x`. Under O2(a) the `cargo tree` diff is zero crates.
- **What 21.7 does NOT do.** No Hub or Node target (AD-24 reserved; FR-57's "or Hub" waits for Epic 25); no `send` hotkey (content-carrying, one agent's input channel — 21-6's reasoning stands); no multi-Row "act on the visible set" mode (single-Row acts; sets belong to the verbs and their own confirms); no server-side sorts (the listing's order stands — a burn-rate sort would be a new listing contract); no writes on quit, no writes from the render path, no config keys added (the switch is a serve flag per O1's recording); no changes to `ps`, the listing, the SSE contract or the verb routes' bodies.
- **Deferred-work decisions (the entries naming this story).** (1) *21-4's live-capture re-check (trigger "story 21.7 (`hekma top`, the surface that polls)")* — **absorb**: the output route re-checks the capture every poll host-side; mark resolved with the route named. (2) *23-4's "`held` Runs in `hekma top`'s hotkeys (21-7)"* — **absorb**: `h`/`l` plus the held count and oldest age in the row; mark resolved. New deferrals at build: a burn-rate/column server sort (trigger: an operator report of needing it at scale); a Hub target (AD-24); mouse support and themes (trigger: an owner ask).
