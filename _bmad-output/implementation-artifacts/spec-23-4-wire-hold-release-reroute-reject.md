## Intent

**Problem:** The shared Metering Proxy (23-1) fenced calls but cannot steer them. The snapshot's `Disposition` carries only `block` bits, so a `pause` or `stop` Breach Action on a `wire` or `announced` Run still falls back to `warn` with a `depth-fallback` Anomaly, `pause`/`resume`/`stop`/`drain` on a child Run or a wire Run are refused (`verb-unavailable`, naming the depth), the hold/release/reroute/reject row of the verb table is `available: false` everywhere, and those verbs take no Selector. An Operator cannot pause a wire Run at all — not while a framework flow runs away, not to drain one, not to move it onto a cheaper route mid-flight: 23-1 stored per-binding reroute routes that nothing reads, the calls store reserves a `hold_end` column that nothing fills, `hekma ps` shows a latched `breach[block]` but no held-call count or oldest age, FR-7's amendment (a wire hold may stand in for a native pause the adapter cannot deliver) is unimplemented, and a held call's re-validation at release (R1.7, deferred from 22-1) cannot exist because nothing can be held.

**Approach:** Ride 23-1's disposition and call state machine — no second decision path. The snapshot's `Disposition` grows the reason set AD-25 names: verb `hold`/`reject`/`reroute` reasons from a new durable `run_dispositions` table (AD-27's shape) and `breach_pause`/`breach_stop` latch bits beside `breach_block`, folded over the ancestor chain exactly as `block` is today, with the precedence reject (verb reject, breach `block`, breach `stop`) > hold (verb hold, breach `pause`) > reroute > pass — and each verb clears only its own reason. In the proxy's call state machine, after the fence and scent checks and the body read: reject-class refuses with 19-2's 402 contract (breach reasons byte for byte; a typed non-retryable row for the verb); hold-class parks the call in a per-Run FIFO arrival-order queue under a per-Run cap and a held-byte budget — past either, a typed retryable hold-full response plus a `hold-full` Anomaly; reroute-class retargets the call to a route configured through `hekma binding`, the route's own custodied key or none (a custodied key never leaves its pinned origins); release drains the queue front-first, re-validating every parked call against the current snapshot — a revoked key answers the typed 401, never a forward (R1.7). Hold end causes (`released|rerouted|rejected|client-timeout|disconnect|process-exit|crash`, plus `shutdown` for a graceful stop's one retryable error) land in the calls store; the proxy reports each Run's held count and oldest held start to the writer, coalesced ≤ 1 s, onto `runs` for `hekma ps`. The verbs are the ruled top-level `hekma hold/release/reroute/reject` (+ `--selector/--dry-run/--yes/--json`, the 21-6 fan-out and set tokens) with Control API parity; `pause`/`resume`/`stop`/`drain` on a Run the table now serves map to hold/release/reject, qualified; `pause`/`resume` at `wire`/`announced` become available (qualified) and child Runs accept their own `pause`/`stop`/`block` at open; a breach `pause` at wire depth now holds and a breach `stop` rejects (latched until re-arm); and a supervised Run whose native pause is `unsupported` uses the wire hold, surfaced as a qualified pause (FR-7's amendment) — never as native. Schema v21; hekma-engine stays 0.12.0.

**Acceptance Criteria:**
- Given a Run holding any mix of disposition reasons over itself or an ancestor (verb reject, breach `block`, breach `stop`, verb hold, breach `pause`, reroute), when a new call arrives, then the effective disposition is the highest per the precedence — a reject-class reason refuses it with 19-2's 402 contract (breach reasons byte for byte, safe methods still exempt), a hold-class reason parks it, else a reroute forwards it to the route, else it passes — and no call is treated by more than one class.
- Given reasons of more than one kind on one Run, when a verb acts, then it clears only its own reason: `release` clears the hold reason and leaves reject, reroute and breach reasons standing (the answer says which remain); `reroute --off` clears only the reroute reason; raising or resetting a ceiling clears its breach reason per reason (re-arm) and releases the calls its latch held; a verb reject is cleared only by the Run ending.
- Given a held Run and three new calls arriving A, B, C, when the Run is released, then their upstream forwards begin in arrival order, each request byte-identical to what was parked (the standard header strip and identity headers still apply), each record carrying disposition `pass` and hold_end `released`, and their usage meters to the Run like any call.
- Given a call already forwarded when the hold lands, then it completes, is billed and meters normally — the hold's answer and the qualified pause note both say that calls already sent complete.
- Given a held Run at the per-Run cap (or over the held-byte budget), when a new call arrives, then it gets the typed retryable hold-full response (`503`, `x-should-retry: true`, `retry-after: 1`), no upstream dial happens, a record with disposition `hold`, outcome `refused`, no hold_end is written, the `hold-full` Anomaly is set on the Run (cleared when the queue drains below the bound), and `hekma ps` lists it.
- Given a Run with calls parked, then `hekma ps` shows the Run `held` with the held-call count and the oldest held call's age (human and `--json`, within the coalesce bound), the exception-first view lists it, and `--json` carries the Run's active disposition reasons.
- Given a held call that ends without a release — the client times out, the connection drops, the owning process exits, or the host crashes — then the per-call record carries which (`client-timeout`, `disconnect`, `process-exit`, `crash`), the Run surfaces the most recent cause (`last_hold_end` and the `held-dropped` Anomaly, cleared when the hold reason clears), and the Run is never reported as cleanly paused.
- Given a call parked under a Run Key that is revoked before release (or whose Run ended, or whose scent mode moved to `enforce`, or that gained a reject reason), when the Run is released, then the parked call is re-validated against the current snapshot and refused with the matching typed response (`401 hekma_credential_revoked`, the unscented 401, or the 402) — never forwarded — and its record names the cause (R1.7).
- Given `hekma binding route add <binding> <route> --upstream <url>` and `hekma reroute <run> --via <binding>/<route>` on a Run with parked calls, then the parked calls are forwarded to the route's upstream (hold_end `rerouted`, disposition `reroute`), new calls go there without waiting, the outbound URI is the route's base plus the call's own rest, and `--off` returns the Run to its own upstream.
- Given a reroute whose route declares no custodied key while the Run's custodied key is not pinned for the route's origin, then the reroute is refused at set time with a remediation naming the origin and the key; given a route with its own key reference, then the swap uses the route's key, exactly one credential reaches the upstream, and the Run's custodied key never leaves its pinned origins (T3.10, R2.6).
- Given `hekma reject <run>` with parked calls, then every parked call receives the typed non-retryable response (status 402, the `proxy-wire v1` envelope, `x-should-retry: false` — the breach body byte for byte for breach reasons, the verb's row otherwise) and new calls are refused the same way, each with a record carrying disposition `reject` and hold_end `rejected`.
- Given a supervised Run with a wire path whose adapter declares pause `unsupported`, when the Operator pauses it, then the Run is held at the metering proxy, the CLI prints a qualifier note (stderr), the event carries the qualifier, `hekma ps` shows `held` — and the pause is never reported as native; given `best-effort`, the native pause proceeds with its existing qualifier; given no wire path, the pause fails fast quoting the declaration as today; given a `pause` Breach Action on such a Run, the wire hold is used, qualified, latched until the ceiling is raised.
- Given a `wire` or `announced` Run with a Policy `pause` action, when usage breaches it, then the Run's new calls hold (no `depth-fallback` Anomaly) until the ceiling is raised, which releases them; given a `stop` action there, then its calls are refused (latched reject) until re-arm; a child Run's own `pause`, `stop` and `block` ceilings are now accepted at open and act on the child's calls over the wire (the verb-depth fixture flips).
- Given a held Run and a graceful host stop, then each parked call receives the retryable `503 hekma_hold_interrupted` and a retried call is held again by the next host; given `kill -9`, then the calls fail as connection errors, every `open_calls` row closes `crash` with hold_end `crash` at the next open, and the hold reason is in the first snapshot the restarted proxy reads — before it accepts a connection.
- Given an `observed` Run, then every hold-family verb fails fast naming the depth; given a `supervised (no wire)` Run, then it fails fast naming the Metering Source; given a Selector matching several Runs, then the verb lists the set, confirms (or `--yes`), applies per Run through the set token, and reports success or refusal per Run with the existing exit classes.
- Given any held, rerouted or rejected call, then exactly one per-call record exists for it with its disposition and hold_end and no request or response byte, token or token id; no refusal body or note carries a limit, a total, an instance name or a credential.

## Design Notes

- **What this story owns, and the rulings it builds on.** AD-25 fixes the reason set {hold, reject, reroute, breach}, the precedence (reject and breach `block` > hold and breach `pause` > reroute > pass) and the clearing rule (each verb clears only its own reason; only raising or resetting a ceiling clears a breach reason). AD-26 fixes the hold queue (per Run, arrival order, no Hekma time bound — only the client's timeout ends a hold), the per-Run cap with the typed retryable hold-full response and an Anomaly, `hold end`'s value set, reroute to configured routes with "a custodied key never leaves its origin", reject as the typed non-retryable `block` response, and the held-count/oldest-age report to the writer (coalesced, ≤ 1 s) onto `runs` for `hekma ps`. AD-23 rules that a hold belongs to its Run, not a connection: a held call may see one retryable error and be re-held. AD-27 names `run_dispositions {run id, reason, route, set_by, set_at}`. The naming ruling makes the verbs top-level `hekma hold/release/reroute/reject` with the house flags. FR-7's amendment allows the wire hold to stand in for a native pause, surfaced as qualified. The security review is draft for ruling: this spec builds R1.7 (held calls re-validated at release) and R2.6's reroute half (a reroute uses its route's own custodied key or none), both already written as binding for this story by 22-1's and 22-2's deferrals.
- **The disposition model, and where it lives.** 23-1's `Disposition` was deliberately "shaped for the hold/reject/reroute reasons a later story adds" — this story fills it. Verb reasons are durable rows in `run_dispositions` (one per reason per Run; the reroute row carries `binding/route`); breach reasons stay latch-derived bits, now classified by action (`breach_block`, `breach_pause`, `breach_stop`; `breach_latched` keeps naming them all for the `x-hekma-breach` header). The writer publishes the whole set in every post-commit hook; the proxy folds it over the ancestor chain with the existing `disposition_over` walk (≤ 8 levels) — an ancestor's hold, reject or reroute applies beneath, exactly as its `block` does (23-1's N11: a hint never escapes its parent's subtree). The PRD's "a verb on a parent reaches its children only through an explicit Selector" governs which Runs a verb writes a reason onto, not how a published reason is enforced — the walk is uniform (Ask First O10 records the tension and the alternative).
- **The hold queue mechanics.** A call is parked AFTER the fence check, the scent check, the call-start record and the body read — so an oversized body is refused before parking, the parked call is complete and forwardable, and its bytes stay counted against the buffered-byte budget for as long as it is held. Two bounds guard memory: the per-Run cap (`max_held_per_run`, default 32 — generous over a typical SDK's concurrency; a held agent's excess calls get a retryable 503, back off and re-queue as slots free) and a global held-byte budget (`max_held_bytes`, default 128 MiB) so a fleet of held Runs cannot starve the passing path's 512 MiB. A parked call selects on: its Run's wake `Notify` (signalled by the disposition job after publish — the writer thread can call `notify_waiters`), the ≤ 250 ms missed-wake re-check, its connection watcher, and host shutdown. On wake it re-runs the disposition computation and re-validation from the CURRENT snapshot — release is not a token handed to parked calls, it is the absence of the reason plus a fresh look at everything else (R1.7's point: revocation, a reject, an ended Run or a moved-to-`enforce` mode all answer at release, never a forward). Release drains front-first: each parked call leaves the queue (forward or refusal) before the next is signalled, so forwards BEGIN in arrival order; completion order is the provider's. A reroute set while calls are held drains the queue to the route and leaves the hold reason standing (each verb clears only its own) — new calls keep parking until release; the docs state this composition plainly (Ask First O8).
- **What the proxy can and cannot see when a held call ends.** FR-56 asks Hekma to record which of "the client's own timeout, the connection dropping or the process exiting" ended a held call. The proxy observes the connection, not the client's reason: an orderly close (the shape an SDK's timeout abort usually takes) records `client-timeout`; a reset or transport error records `disconnect`; a process-owning Run's process exit (which the engine observes) drops its parked calls as `process-exit`; a host crash is closed at the next open as `crash`. The docs say these are the observables. A graceful stop adds `shutdown`: the held connection is answered with one retryable 503 (`hekma_hold_interrupted`) so the client's retry lands on the next host (or Handoff Mode's successor, 24-2) and is held again — AD-23's rule, built in its graceful shape here. `shutdown` is an additive value beyond the spine's seven (Ask First O3).
- **Reject's response.** 19-2's contract is the reuse: status 402, the `proxy-wire v1` envelope, `x-should-retry: false`, no limit or content in the body. Breach reasons (`block`, and now `stop`) answer byte for byte as today — the latch supplies the `error.code`. A verb reject has no latch, so it gets its own additive row `402 hekma_run_reject` (`x-should-retry: false`): the same status, envelope and non-retryable posture, a type that does not tell an agent it is out of budget when an Operator paused it (Ask First O7; the story's "reuses 19.2's typed non-retryable response" is satisfied by the contract, not the literal budget body). Safe methods pass a verb reject too, mirroring the fence (a fenced agent's probes stay alive).
- **Reroute: paths, keys, money.** A route is 23-1's stored `{name, upstream base, optional custodied-key reference}` per binding — this story is its first reader. The outbound URI is `<route base> + <the call's own rest> + <query>`, authority-checked against the route's base after canonicalisation (the same check as the Run's own upstream); the Operator configures the base to fit the path shape (an OpenAI-shaped rest `/v1/chat/completions` wants a bare-origin base). No protocol translation and no request rewrite: the route moves the call's origin, it does not edit the body — the PRD's "another configured model" is met by pointing the route at a gateway that serves one (a model-rewriting route is deferred with its trigger; Ask First O4). Keys follow R2.6/T3.10 exactly: the route's own key when it declares one; the Run's custodied key only when the route's origin is on that key's pins (validated at set time, re-checked per call by 22-2's pin check — a tampered route fails closed); otherwise the call keeps whatever credential it presented (the pre-custody posture). Money does not move: usage meters to the same Run, budgets and ceilings apply unchanged, and pricing keeps 23-1's rule — the model reported in the RESPONSE prices the row, so a rerouted call prices at the route's served model, with no retroactive repricing.
- **The FR-7 dispatch (qualified, never native).** A supervised Run's pause keeps FR-7's native ladder: `guaranteed` and `best-effort` behave exactly as today (best-effort with its existing qualifier), and the explicit ask for a wire hold on any wire-path Run is `hekma hold`. The amendment fills the two gaps: native `unsupported` + a wire path → the pause becomes a wire hold with a qualifier (a stderr note in the CLI, a qualifier field in the event — the `pause-best-effort` pattern — and `held` on `ps`), never a native-pause claim; and a `pause` Breach Action on such a Run uses the wire hold, qualified. `unsupported` with no wire path still fails fast quoting the declaration. At `wire`/`announced` depth the verb table already rules `pause`/`resume` qualified holds/releases — this story delivers those cells, with the same qualifier surfaces. A wire hold on a process-owning Run does not touch its process: the in-process children's calls hold with it (the ancestor walk), which is also how a paused agent's children stop spending without each child needing its own verb.
- **Breach actions at wire depth, and the fallback retiring.** `action_executable` extends to `pause`/`stop` at any depth with a wire path, so a wire Run's `pause` action now HOLDS (a latched hold reason cleared by re-arm, which also releases the queue) and its `stop` action refuses (a latched reject reason) — FR-49's Breach Action row, "as the verbs above (block as reject), latched until the ceiling is raised or reset". The `depth-fallback` Anomaly stays only where no wire path exists. A breach `stop` does NOT end the Lease (a latched action is reversible; the operator `stop` verb is the terminal one). The operator `stop` on a `wire` Run sets the reject reason and ends the Run (cause `operator-stop`); on an `announced` Run it also ends the Lease (23-2), whose sweep releases the identity row — without 23-2's identity release a binding Run stopped this way would strand its identity; the build rides 23-2 (Ask First O9).
- **Restarts, crashes and the sweeper.** A hold reason is a durable row: after a crash or restart it is in the first snapshot the proxy reads, before the first accept (the same guarantee 23-1 built for `block`). Parked calls are connections, not rows: a graceful stop answers them with the retryable 503, a crash breaks them (their `open_calls` rows close `crash`), and the retried calls are held again — "a hold belongs to its Run". The held-count/oldest-age columns are refreshed by the proxy's reports and reset at open. 23-2's inactivity sweeper skips a Run with an active hold-class reason: a hold is an Operator verb, and silence-sweeping a Run its Operator is deliberately holding would be an unrequested stop (NFR-9); the silent window resumes when the hold clears.
- **Where the hold sits against the scent verdict.** 22-3 fixed the order fence-first "and before the call-start record"; the hold slots into the same place — after the fence, after the scent verdict, before the call-start record for the parking decision (an unscented call under `enforce` is refused, never parked: a call the proxy would not serve is never given a seat). Unknown and revoked keys are refused before identification can even attribute a Run, as today.
- **`proxy-wire v1` additions** (additive rows; the table in `docs/metering-proxy.md` grows): `402 hekma_run_reject` (verb reject; `x-should-retry: false`); `503 hekma_hold_full` (retryable, `retry-after: 1`); `503 hekma_hold_interrupted` (retryable, `retry-after: 1` — only the graceful-stop interruption). No body carries a limit, total, instance name, token or content. The held call's relayed response (on release) carries `x-hekma-breach` when a breach is latched, like any relayed response.
- **Per-call records.** `disposition ∈ {pass, block, enforce, hold, reroute, reject}` (the value is what the proxy finally did); `hold_end` is non-NULL only for calls that were parked ({released, rerouted, rejected} when a verb drained them; {client-timeout, disconnect, process-exit, crash, shutdown} when they ended held); a hold-full refusal is disposition `hold`, outcome `refused`, hold_end NULL (it was never parked). The calls store moves to `user_version` 2 for the column; the CHECK-free disposition column is why 22-3 needed no step and this story needs only the one.
- **Schema v21; hekma-engine stays 0.12.0** (the cycle rule; v18 = 23-1, v19 = 22-2, v20 = 23-2's plan; take the next number if the chain moved). Additive and one-way: one table, three columns, the calls-store column; no backfill (`held_call_count` defaults 0; a Run held across the upgrade simply has no parked calls — its reason row, if any, predates none). New public types and variants (`RerouteTarget`, `HoldEnd`, `CallDisposition` variants, `WireError` rows, `EngineEvent::Disposition`, the facade verbs, the two options fields, the additive `RunDocument` fields) ride existing schema versions per the 22-1/23-1 additive-field precedent.
- **Threats considered** (review ids where they exist; N-ids are this story's):
  - a held call released after its credential was revoked or its Run ended [T1.6(b), R1.7] → re-validation against the current snapshot at wake; the typed 401/402, never a forward;
  - reroute spending one origin's key on another route [T3.10, R2.6] → the route's own key or none; pin validation at set time; 22-2's per-call pin check fails closed;
  - a reroute route redirecting a custodied call [T3.3/T3.4/T3.5] → the canonical authority check against the ROUTE's base; redirects relayed, never followed; `https`-only under custody (22-2);
  - memory exhaustion through held bodies [N1] → the per-Run cap and the held-byte budget; over either, a retryable typed refusal;
  - a stuck hold after a missed wake [N2] → the ≤ 250 ms re-check tick; the wake is an optimization, the snapshot is the truth;
  - the sweeper ending a deliberately held Run [N3] → the hold-class skip in the sweep predicate (NFR-9);
  - an unprivileged local process filling a Run's hold queue [N4] → the same attribution posture as 23-1 (loopback, no proxy credential): such calls are billed to and held by the Run they name, never custody-eligible (P4), and the cap bounds them;
  - a pause masquerading as native [N5] → the qualifier on every surface (stderr note, event field, `held` status); "never as native" is FR-7's amendment tested;
  - hold ordering subverted (a later call passing an earlier one) [N6] → front-first drain; the queue is FIFO and a re-parked call keeps its slot;
  - a hold-full response treated as fatal by an SDK [N7] → 503 + `x-should-retry: true` + `retry-after: 1` (the SDK-default retry), never a 4xx;
  - held bytes double-counted against the passing budget [N8] → a held request keeps its permit; the held budget is a slice of the same semaphore total, not an addition to it.
- **What 23-4 does NOT do.** No mid-stream hold or incremental SSE relay (buffered whole, as AD-26 rules; the named trigger stands); no Handoff Mode or socket handoff (24-2 — this story builds the graceful retryable shape it formalizes); no per-call read surface for Hosts (19.4); no OTLP counters (24-5); no model-rewriting routes (deferred with its trigger); no hold TTL (no Hekma time bound, per AD-26; a TTL deferral trigger: an Operator report of holds outliving their clients); no Caller- or Run-Key-initiated holds (Operator/Host bearer only, AD-20); no `observed`-depth verbs (fails fast, per FR-49); no pause of anything without a verb, a Breach Action or `enforce` (NFR-9).
- **Deferrals (new entries at build) and the existing entries naming this story.** New: a model-rewriting route option (trigger: a route needing body edits); a hold TTL option (trigger: an Operator report); `held` Runs in `hekma top`'s hotkeys (21-7). Existing: 19-2's fence-on-the-state-surface entry — **resolved** (the full disposition slice: held count, oldest age, hold end causes on `runs` and `hekma ps`); 21-2's child pause/stop/block cells — **resolved** (accepted at open with a wire path; fixture flipped); 21-6's hold-family fan-out — **resolved** (the verbs take Selectors through the fan-out); 22-1's R1.7 held-call re-validation — **resolved** (re-validation at wake).

## Build Conventions

- User-facing text (docs, CLI help and messages, error bodies, response headers, CHANGELOG, RELEASE_NOTES) never carries planning ids (no `23-4`, `FR-56`, `AD-26`, `R1.7`, `T3.10`) and never the word "pivot"; the first production Host stays unnamed. Code comments and `_bmad-output/` may cite ids. Proposed wording, for example: "This Run's calls are on hold. New calls wait at the metering proxy; calls already sent complete and are billed." · "This Run is holding 32 calls already, so this call was not held. Retry shortly, or release the Run." · "This Run's calls are being sent to the route 'fast'." · "This Run's calls are rejected: an operator stopped them at the metering proxy." · "Paused as a wire hold: the process keeps running and its model calls wait at the metering proxy." · "The hold outlives this restart: a retried call is held again." · "This held call was not sent: its Run Key was revoked while it waited."
- `docs/runs.md`'s "In development" row resolves; `docs/metering-proxy.md` states the cooperative scope (an agent that ignores its base URL is neither held nor rejected), the no-Hekma-time-bound rule, and the observables behind the hold-end names.

## Ask First

Each is a public-contract or scope choice; the recommendation is the spec's current text. **O-items are the owner's (Islam's)** — product calls this story makes on his behalf and places where the PRD, the spine and the review rub against each other; every O-item that changes a public contract (status codes, wire bodies, headers, CLI flags, config keys, event schemas, Run statuses) needs his confirmation. The numbered items are the orchestrator's. Until ruled, the build proceeds on the recommended option and the PR stays unmerged past review.

- **O1. The hold cap's default and the hold-full response.** Options: (a) `max_held_per_run` 32 + a 128 MiB held-byte budget, refusal `503 hekma_hold_full` with `x-should-retry: true` and `retry-after: 1`, plus the `hold-full` Anomaly (recommended — 32 covers a realistic SDK burst; the byte budget keeps a fleet of held Runs from starving the passing path; 503 + retryable is the SDK-default retry, so no agent crash-loops on a full queue); (b) a smaller cap (16) with the same response; (c) no cap, only the byte budget (a Run could hold thousands of empty seats — refused calls are cheaper than parked ones, but the count is unbounded). **Public contract** (the status/type/retry row and the option fields' defaults). Meanwhile: (a).
- **O2. How long a held call may wait.** AD-26 already rules "no Hekma time bound — only the client's timeout ends a hold". Options: (a) keep the ruling (recommended — a hold is a pause; a Hekma timeout would unpause by surprise, and NFR-9's spirit is that only a verb or a breach acts); (b) an optional per-Run hold TTL (`--for 10m`) that releases-or-rejects on expiry (a new knob and a new end cause; deferred with its trigger). The caller sees its own SDK timeout error; the proxy records the observable (`client-timeout` on an orderly close). Meanwhile: (a), the TTL deferred.
- **O3. Whether a hold survives an engine restart.** Held calls are open connections; the reason is a durable row. Options: (a) AD-23's ruling, built here: the reason survives (republished before the first accept), parked calls receive one retryable `503 hekma_hold_interrupted` at a graceful stop (a `kill -9` breaks the connection; either way the row closes at the next open) and a retried call is held again (recommended — the hold belongs to the Run, not the connection; the alternative strands the reason or the calls); (b) drop the reason at restart (an Operator's hold silently vanishes — rejected); (c) keep parked calls across a restart (impossible — connections do not survive a process). **Public contract** (the new wire row and the `shutdown` hold-end value). Meanwhile: (a).
- **O4. Reroute's scope and its money.** Options: (a) routes are origins, exactly AD-26 and the story bullet ("routes configured through `hekma binding`"): a reroute may cross providers when the Operator configures the route (no protocol translation; the request body is never edited — the PRD's "another configured model" is served by pointing the route at a gateway that serves one); budgets and ceilings are unchanged; pricing keeps the response-model rule, so a rerouted call prices at the model the route served, never retroactively (recommended); (b) a model-rewriting route option that edits the body's `model` (touches content, breaks the no-body-edits posture, and is one more thing to scent — deferred with its trigger); (c) same-provider-origin-only reroutes (refuses the cheap-gateway use case). **Public contract** (route semantics + docs). Meanwhile: (a).
- **O5. `hekma pause` as a wire hold, and how "qualified" shows.** The verb × depth table already rules `pause`/`resume` at `wire`/`announced` "qualified: holds / releases the Run's calls" — this story delivers it. Open: (a) at those depths `pause` IS the hold verb (qualified: a stderr note, a qualifier field in the event, `held` on `ps`); on a SUPERVISED Run the native ladder stands, with FR-7's amendment filling only the `unsupported` + wire path gap (recommended — the amendment's own wording; `best-effort` keeps its native pause and qualifier; the explicit ask for a hold on any wire-path Run is `hekma hold`); (b) `pause` falls back to a hold whenever native pause is not `guaranteed` (silently replaces best-effort native pause — changes existing behaviour the PRD keeps); (c) no mapping (the table cell stays undelivered — the story fails its own bullet). **Public contract** (Run status rendering, event fields). Meanwhile: (a).
- **O6. The CLI verbs and Control API routes.** The naming ruling already fixes top-level `hekma hold`/`release`/`reroute`/`reject` with the house flags. To confirm: `hekma reroute <RUN_ID|--selector> --via <binding>/<route>` and `--off` to clear (recommended — `--via` names the route's two-level key without a new noun; `--off` is the route's own clear, honouring "each verb clears only its own"); Control API `POST /v0/runs/{id}/hold|release|reject|reroute` (`{"route": "b/r"}` / `null`) + the four `/v0/runs/<verb>` set forms with `{"selector","set_token"}` (the 21-6 shape, byte-consistent with stop/pause). **Public contract** (flags, routes, bodies). Meanwhile: as recommended.
- **O7. The verb-reject body.** 19-2's contract (402, the envelope, `x-should-retry: false`) is reused for every reject; the question is the literal body for a VERB reject, which has no latch to name a dimension/scope. Options: (a) a new additive row `402 hekma_run_reject` (recommended — the same status and non-retryable posture, but a type that does not tell an agent it is out of budget when an Operator stopped it; breach rejects stay byte-for-byte `hekma_budget_block`); (b) literal reuse of `hekma_budget_block` with a fixed code (a verb reject would wear a budget code it did not earn). **Public contract** (a new `proxy-wire v1` row). Meanwhile: (a).
- **O8. Reroute under a hold.** FR-56 says a reroute forwards the held calls; AD-25 says each verb clears only its own reason. Options: (a) spine-literal (recommended): the reroute drains the queue to the route AND leaves the hold standing — new calls keep parking until `release`; the docs state the composition and the two-step flow (reroute then release) is explicit; (b) a reroute also clears the hold (one verb, two reasons cleared — an AD-25 amendment, Islam's). **Scope/contract wording**; either way the drain behaviour is the same. Meanwhile: (a).
- **O9. What `stop` means at wire depth.** Options: (a) the operator `stop` verb on a `wire` Run sets the reject reason and ends the Run (cause `operator-stop`); on an `announced` Run it also ends the Lease (FR-49's cell); a BREACH `stop` is latched only and never ends anything (recommended — verbs are terminal, latches are reversible); (b) stop-at-wire refuses pending a dedicated end verb (leaves FR-49's cell undelivered); (c) stop-at-wire only sets the reject reason and never ends the Run (a "stopped" Run that lingers open and keeps its keys). **Public contract** (Run end semantics). Meanwhile: (a).
- **O10. Does a verb-set reason on a parent apply beneath it?** AD-25's disposition walk (23-1 built it for `block`: an ancestor's reason applies over the Runs beneath) meets FR-49's "a verb on a parent reaches its children only through an explicit Selector or flag".
