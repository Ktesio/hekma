## Intent

**Problem:** Epic 18 shipped its four service-grade behaviors story by story — readiness gating (18-1), declared liveness (18-2), exit-code classes (18-3), cooperative pause + drain (18-4) — each proven by engine-suite drills against minimal fixtures. What does not exist is the epic's INTEGRATION PROOF: one real gateway-shaped service agent that declares ALL of it at once, and a Conformance Test Kit that holds ANY adapter to the same behaviors section by section. The TCK today (8 sections) still describes the pre-epic lifecycle (its crash leg even hardcodes the "300ms readiness window" world). And the `hermes` kind's ratified retirement path (14-5, AD-19 amendment) is BLOCKED on exactly this: "removal waits for the service-mode successor."

**Approach:** Three deliverables, no new engine behavior. (1) **The reference manifest**: a canonical gateway-shaped agent — an API server with readiness on its models endpoint (`[readiness.http_get]` against the loopback port it opens), heartbeat liveness (`[liveness.heartbeat_file]`), exit-75 restart (`[exit_codes] restart_requested = [75]`), and a cooperative pause pair + `[drain]` with an idle marker — the one manifest that declares the whole epic. It lives in the conformance kit as the TCK's gateway subject (materialized per-run) and is shown in `docs/manifest.md` as THE reference example. (2) **The gateway fake**: the kit's `fake_agent` composed — its existing flags already cover every leg (`--http-ready`, `--heartbeat-file`, `--watch-sentinel`, `--idle-after-ms`, `--exit-with`); the reference manifest's start command is ONE invocation composing them. Only what composition genuinely lacks is added (and recorded). (3) **Four TCK sections** — `readiness`, `liveness`, `exit_classes`, `drain` — each consulting the subject's DECLARATION: declared → the section proves the behavior end-to-end on the subject (the twin-leg pattern the existing sections use: a healthy leg + a failing leg); undeclared → `not_applicable` with the reason naming the absence (the `pause` section's honest-degradation template). The gateway manifest passes all four; the legacy mock subjects degrade honestly. Plus the **hermes successor note**: the deprecation surface (adapter-contract's policy area, the commands/agents hermes notes, CHANGELOG/RELEASE_NOTES) records that the service-mode successor HAS LANDED — AD-19's wait is satisfied; removal itself stays at a future MAJOR per the ratified policy (NOT this story).

## Design Notes

- **Composition over construction.** The epic's fake "behaves like" a gateway; the kit's fake_agent ALREADY behaves like every PART of one (the 18-x stories each shipped the fixture leg their drills needed — `--http-ready`, `--heartbeat-file`, `--watch-sentinel`/`--touch`, `--idle-after-ms`, `--exit-with`). The reference manifest composes them into one command; the story's fixture work is verifying the composition and filling genuine gaps only. This is why the story carries no new server machinery: a gateway's observable contract (from the engine's seat) is exactly the signals the four sections read.
- **The TCK tests the ADAPTER, and absence is honest.** The `pause` section set the template: an Unsupported declaration is not a failure — it reads `not_applicable` naming the declaration. The four new sections inherit it: a minimal adapter that declares no `[readiness]` is not penalized for it. What FAILS is a declaration that lies (declared but the behavior breaks) — that is the conformance contract's whole shape, and each new section's failing leg pins it.
- **The failing legs need deterministic twins, not mutations of a live subject.** The existing sections arm behavior through the MANIFEST (the crash twin's args, the never policy) — never by editing a running subject. The new failing legs follow: a never-ready twin (the endpoint answers nothing / a wrong status), a signal-killed twin (`--heartbeat-stop-after`), an exit-75 twin, a never-idle twin (no idle marker written). All composable fixture flags — this is why 18-1..18-4's fixture discipline pays off now.
- **Twelve sections, one report, additive.** The section ids are constants on the report; the subset machinery (`TckConfig`) and the default-all behavior are untouched in shape. `run_conformance` on the gateway subject is the epic's closing integration test — it runs everything the epic shipped against the one manifest that declares it all.
- **The reference manifest is documentation AND fixture, once.** The kit's copy is the executable truth (`gateway.rs`); `docs/manifest.md` SHOWS it as the composed example (the docs' job is the reader's mental model — each section cross-linked). The drift risk is governed by the section-set pin (the kit's manifest declares exactly five things; the docs example shows the same five) — a byte-equality pin between docs and code would couple two release surfaces that change for different reasons; the section-set equality is the honest invariant.
- **AD-19's wait ends with a note, not a removal.** The ratified retirement policy (deprecations announced ≥1 minor ahead; removals only at next MAJOR) is untouched; this story LANDS the successor the amendment waited for and says so on the deprecation surface. The actual `hermes` kind removal is a future-major decision with its own migration story — recording "successor landed" here is the amendment's letter.
- **No engine changes is a feature, and a constraint.** The four behaviors are DONE and pinned; this story assembles proof around them. If implementation finds an ENGINE defect while composing (e.g. two declarations interacting badly on one manifest), that is a FINDING to surface — fix in this story only if it blocks the reference manifest outright, and record it loudly in the Spec Change Log either way.
