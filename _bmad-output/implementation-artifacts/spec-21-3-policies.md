## Intent

**Problem:** Budgets are per-instance config keys and nothing more. An Operator cannot set one ceiling for every Run a label names, cannot give wire Runs a Rate source, and the implicit Breach Action default — `pause` since story 3-2 — freezes a looping agent mid-task the Operator never opted into stopping (NFR-9's spirit; the 2026-10-30 FR-21 amendment). The default lives in code (`BreachAction::default()` via `.unwrap_or_default()` in `resolve_token_budget`/`resolve_cost`), so no surface can show or change it, and 21-9's `labels_changed` hook is a no-op with nothing to re-resolve.

**Approach:** A `policies` table (schema v15) plus one pure resolution function in the domain core (`domain::runs::policy::resolve`) that every surface calls: explicit Run limits first, then explicit instance config (any FR-11 layer), then per-limit the matching Policy with the most specific Selector (strict term-set superset, ties to the tightest value), then the stored, editable `default` Policy (Breach Action `warn`, Scent-Check `off` until 22.3, an empty model-keyed Rate table). The default Breach Action moves out of the code and into that row. A crash-safe upgrade (pending list in state.db → idempotent `config.toml` writes under their locks → markers + one `breach_default_upgraded` event + list cleared in one transaction) writes `pause` explicitly into every pre-change instance that relied on the implicit default, with a "kept on pause by upgrade" note; a malformed `breach_action` fails closed to `pause`. A Policy Breach Action a Run's Control Depth cannot execute falls back to `warn` plus the `depth-fallback` Anomaly, and create/change reports the fallback count. `hekma policy` (routed through the Service Host like `hekma label`) and `/v0/policies` CRUD (Operator bearer only) manage Policies; every change is an event; a change re-resolves every matched open Run in the writer's next batch — lowering below usage breaches at once, raising re-arms the latch and clears matching `block` fence reasons. Resolved Policies join the published snapshot.

**Acceptance Criteria:**
- Given a fresh state dir, when the engine opens, then `user_version` is 15, exactly one `default` Policy exists (no ceilings, action `warn`, scent `off`, an empty Rate table), and no config layer carries `budget.breach_action`; a newly registered instance with no explicit action and no matching Policy resolves action `warn`, and its registration response names `warn`.
- Given a v14 state dir with instances A (no `budget.breach_action` anywhere), B (explicit `stop` at the instance layer) and C (a kind-default layer carrying `warn` — pinned through the kind-default seam), when the engine opens, then A's instance layer gains `budget.breach_action = "pause"` written explicitly, B and C are untouched (C resolves its kind layer's `warn`), A carries the "kept on pause by upgrade" note in the Fleet listing and on its Runs (human and `--json`), exactly one `breach_default_upgraded` event is on the bus and in the outbox listing A, and a breach on A still pauses.
- Given the upgrade interrupted at each stage — (a) after the state.db transaction, before any `config.toml` write; (b) between `config.toml` writes; (c) after the writes, before the closing transaction — when the engine reopens, then it resumes from the pending list, no instance ever resolves `warn` through the gap (pending and marker rows resolve `pause`), the `config.toml` writes are idempotent, and the event fires exactly once across all attempts; an instance whose `config.toml` is missing or unwritable keeps `pause` through its marker with a diagnostic.
- Given a hand-edited `config.toml` with `breach_action = "throttle"`, when limits resolve, then the action is `pause` (fail closed) and a diagnostic names the value and layer — never the new `warn` default.
- Given Policies P1 `team=core` (tokens per-run 1M, action `pause`) and P2 `team=core,env=prod` (tokens per-run 2M, action `warn`) and a Run bound `team=core,env=prod`, then P2's Selector is the strict superset, so the per-run token ceiling is 2M from P2 — the most specific Selector wins per limit, whatever the value; given two Policies with incomparable Selectors (neither a term-set superset, e.g. `a=1,b=2` vs `a=1,c=3`) both setting the action (`pause` vs `warn`), the tie resolves to `pause` (the tightest), and a ceiling tie resolves to the lower value; an explicit limit on the Run or the instance outranks both.
- Given a Run whose Caller label `team=core` matches a Policy's Selector, the Policy does NOT apply (bound labels only); a bound `team=core` on the same Run makes it apply.
- Given a Policy with action `pause` matched by a child Run at depth `announced`, then the child's effective action is `warn`, it carries the `depth-fallback` Anomaly naming the depth and the Policy, and `hekma policy create|change` reported the fallback count before writing; when the Run's depth later supports the action, the Anomaly clears and the action takes effect.
- Given a Policy Cost Cap and an instance whose `model` is absent from the Rate table with no other Rate source, then the Run carries the `unpriced-model` Anomaly naming the model and the Policy, and the Anomaly clears when a Rate resolves (a table entry added, an instance Rate set).
- Given an open Run under a matched Policy, when the Operator lowers the Policy's per-run token ceiling below the Run's usage, then the breach records in that writer batch (breach row, latch, outbox, `breach` Anomaly, process action applied / fence raised per the action) without waiting for the next usage event — proven for tokens AND dollars, per-run AND cumulative; when the Operator raises a breached ceiling above the usage, then the latch rows clear, the `breach` Anomaly clears and the next crossing re-fires.
- Given a `block`-action Policy breach that raised a fence with TWO latched reasons (tokens per-run and dollars cumulative), when the Operator raises only the token ceiling above the totals, then the token reason clears, the dollars reason holds and the listener is STILL fenced; raising the dollar ceiling too unfences it (per-reason clearing, pinned).
- Given a bound-label change from any 21-9 path (verb, config write, relaunch, adoption) and a Run creation, then the Run's Policies re-resolve in the same writer job and the published snapshot entry carries the resolution (pinned by a test, as 21-9 pinned the hook call).
- Given `hekma policy list|show` (`--json`), `create`/`change`/`delete` with `--dry-run`, then reads never start a host, writes route through the local Service Host, the dry run reports the matched set and fallback count without writing, and the exit codes follow the frozen table (3 unknown Policy, 2 invalid Selector/limits/action/delete-of-`default`, 1 store/host).
- Given `GET /v0/policies` and `GET/POST/PATCH/DELETE /v0/policies/{name}` with the operator bearer, then CRUD answers `200/201/204`, create/change answers include `matched` and `fallbacks`, a duplicate name is `409 policy-exists`, `default` cannot be deleted or given a Selector (`409 policy-default`), a bad body is `400 invalid_body` / `422` for a wrong type or unknown field (21-9's status pins), and no credential is `401`; every committed change is one `Policy` event on the bus, in the outbox and on SSE.
- Given the governance vectors, then a `policy` case kind pins the resolution rules above, `vectors_version` is 1.3.0, every 1.2.0 case is byte-identical, and the verifier passes.
- Given handoff: fmt, clippy `-D warnings`, the workspace tests, `check_docs.py` (+ `--self-test`), `test_automation.py` pass; changed-line coverage ≥ 95%; AI-55 two-pass review done (money code).

## Design Notes

- **The pure resolver (AD-25's "one pure function").** `domain::runs::policy::resolve(&ResolutionInput) -> PolicyResolution`, I/O-free, public and serialized (the vectors artifact carries its input/output). Inputs: the Run's depth + wire path, its bound labels, its explicit `RunLimits`, the instance's explicit limits (already layer-merged: `{token per-run/cumulative, dollar per-run/cumulative micros, action, rate}` where an unset field is absent), the policy set (each `{name, selector terms, limits, rate}`, the default included with no selector), the resolved `model` string, and optional caller limits (no surface yet; threaded so 22.x wires in without touching the function). Output: the effective `TokenBudget`, `CostCap`, action, `ScentCheckMode`, `Rate`, a `LimitSource` per limit (`run` | `explicit` | `Policy(name)` | `default` | `unset`), the `effective_action` after depth fallback, the fallback detail, and the unpriced-cap signal.
- **"Most specific" precisely.** Selector A is more specific than B iff A's term SET is a strict superset of B's (`set(A.terms) ⊃ set(B.terms)`; terms are exact `(key, value)` pairs — term count alone never decides). Per limit, candidates are matching Policies that SET that limit; every candidate strictly less specific than another is dropped; the remaining maximal candidates tie and the tie resolves to the tightest value — ceilings (tokens and dollars): the minimum; Breach Action: `warn` < `pause` < `stop` < `block`; Scent-Check: `off` < `shadow` < `enforce`. Equal values under a tie name the alphabetically-first Policy as the source (deterministic events and surfaces). Selectors match `SelectorScope::BoundOnly` labels only (`Selector::matches`, 21-9).
- **Precedence, whole chain (per limit).** (1) A malformed explicit `breach_action` anywhere → `pause` + diagnostic (fail closed, AD-7). (2) Explicit Run limits (`run_limits`, operator/Host — the tighter scope wins, the FR-11 spirit). (3) Explicit instance config (any FR-11 layer, merged; the FR-21 upgrade write lands here). (4) Policies per the most-specific rule. (5) The `default` Policy's value. (6) Unset. Caller limits (none today) enter as a candidate only while tighter than the resolved value — they can tighten, never loosen (FR-53/FR-60). The action limit always resolves: the default Policy sets `warn`.
- **The `default` Policy row.** `name = 'default'`, no Selector (it is the fallback layer, not a match-all Selector — a match-all named Policy is refused: non-default Policies require a non-empty Selector), no ceilings, `breach_action = 'warn'`, `scent_check = 'off'` (Q9 interim: seeded `off`; 22.3 decides environments and NEVER overwrites an Operator-edited default), an empty `policy_rates` table. Editable like any Policy (the Operator may set ceilings on it — a fleet-wide standing cap — or change its action). It cannot be deleted or given a Selector. The code's `BreachAction::default()` derive stays `Pause` (19-2's pin) and is used only to seed the row and as the fail-closed value; the engine-default config layer carries no `budget.breach_action` (AD-9 amendment, pinned by test).
- **The Rate chain and the model-keyed table.** Instance `cost.rate.*` (both directions, else absent — a half-configured Rate stays "no Rate" and falls through, with the existing surfaced note) → the winning Policy's flat `Rate` (specificity as above; a tie resolves to the higher `input+output` micros sum — the conservative, overstate-cost direction — then the name) → the default Policy's `policy_rates` entry for the instance's resolved `model` key: exact, case-sensitive, no prefix or wildcard matching. The table ships EMPTY (no invented prices in money code); the Operator fills it (`hekma policy change default --rate-for <model> --rate-input $3.00 --rate-output $15.00`). Rates stamp usage rows at commit; a table change re-prices future consumption only (no retroactive repricing, unchanged). Flat Rates live on named Policies; model-keyed tables live only on `default` (a named Policy's Runs are label-shaped, not model-shaped — a table there is theme-D work if ever asked for).
- **Unpriced caps (the fail-open fix).** When the resolved `CostCap` has any scope set AND no Rate resolves AND at least one ceiling's source is a Policy: the Run gains `Anomaly::UnpricedModel` (`unpriced-model`), naming the model (or "no model configured") and the Policy; surfaces in Fleet/Run reads and events; clears when a Rate resolves. Explicit-instance caps with no Rate keep today's documented inert-with-notice (FR-20) — no Anomaly (scope discipline: the story names the Policy case).
- **Depth fallback.** The effective action is the resolved action iff the Run's (depth, wire_path) can execute it, else `warn`: supervised process-owning runs execute `pause`/`stop` always, `block` only with a wire path; `supervised (no wire)` and every depth below `supervised` cannot execute `block`; depths below `supervised` cannot execute `pause`/`stop` until wire hold/reject land (23.4) — so today they fall back. This reuses 21-2's `Anomaly::DepthFallback` and its set/clear rules (one condition: an action the depth cannot execute, however it was sourced; the resolution names the Policy). The exec test extends `domain/runs/verbs.rs`'s one table (`action_refusal`'s data), so the fixture and resolution cannot drift. The fallback applies per Run at resolution time and clears when the depth supports the action again (FR-49's rule).
- **Where resolution runs.** Six paths, one function: (1) Run creation (the spawn job, `open_child`) — fills the 21-9 deferral (Fibery 607); (2) `labels_changed` (the 21-9 hook) inside the label job; (3) the Policy change job (below); (4) depth changes (`sync_depth`); (5) a `budget.*`/`cost.rate.*` config write re-resolving the instance's open process-owning Run (TOML first, then the job — the 21-2 labels precedent); (6) `eval_input` at each usage event — the enforcement truth, resolved LIVE (config re-read per event, FR-22's rule, plus the policy set and the Run's row through one read) so no missed re-resolve path can silently stale money enforcement. Paths 1-5 write the stored `run_policy` row (surfaces, snapshot, events); path 6 recomputes; a consistency test pins they agree after every re-resolve path. A corrupt/missing default Policy row at read time fails closed to `pause` with a diagnostic (the malformed-value rule extended to the store).
- **The Policy change job (Q11 interim: follow the latest).** One writer job: write the `policies`/`policy_rates` rows; compute the matched set (non-ended Runs whose bound labels match — a `default` change matches every non-ended Run); for each matched Run re-resolve, write `run_policy`, set/clear `depth-fallback` and `unpriced-model`, republish the snapshot entry; then for each matched Run run `governance::decide` on its own arms over its subtree totals with its latches: a lowered ceiling at-or-below usage fires the breach AT ONCE (breach row, latch row, outbox, `breach` Anomaly, `BudgetBreachEvent`; process actions returned to the caller which applies them per D2; `block` raises the fence post-commit); a raised ceiling above the totals re-arms: delete that Run's latch rows for the re-armed (dimension, scope), clear the `breach` Anomaly when no latch remains, and clear matching `WireFence` reasons. **The fence clear is PER REASON** (amendment 2, orchestrator review 2026-11-09): a raise clears only the `(dimension, scope)` reasons whose re-resolved ceiling now sits ABOVE that Run's totals; a fence holding any other latched `block` reason STAYS UP (raise one of two latched reasons → still fenced; raise both → unfenced — pinned). Ancestors need no special case: a Run whose arms changed is itself matched; ancestor ceilings unchanged by this Policy were never affected (each level's arms come from its own resolution — 21-2's `decide_chain` at the next commit stays consistent). Delete re-resolves the matched set the same way (limits may loosen). 21.6 owns the SAME rule for `hekma budget`/config raises; FR-60's own testable consequence (a POLICY change re-arms) is met here, and 21.6 generalizes the trigger, reusing this code.
- **The upgrade (schema v15, AD-7's crash order).** The migration runs at writer open (the Service Host's engine — the one writer; a read-only CLI open of a v14 dir answers `NeedsMigration` and the CLI finds/starts the host, exactly 21-4's flow). Three stages:
  1. **Transaction A** (`BEGIN IMMEDIATE`, the v14→15 step): the DDL (`policies`, `policy_rates`, `run_policy`, `breach_default_upgrade`), the seeded `default` row, and the pending list — one row per registered instance whose persisted layers carry no `budget.breach_action`. The test is the REAL resolution, not a file grep: the three persisted layers the instance resolves through are the embedded engine-default const (`engine_defaults_layer()`, which never carries the key — pinned), the kind-default layer (`kind_defaults_layer(kind)` — an in-memory adapter-supplied table, empty for every kind today, not a file), and the Agent Home instance `config.toml`; the migration resolves them through `config::resolve` and marks the instance pending iff `budget.breach_action` is ABSENT from the resolved set (a malformed value at any layer is PRESENT — the instance is not pending, and the fail-closed malformed rule keeps it `pause`). The invocation-override layer is ephemeral, not persisted, and ignored for the upgrade (an override still outranks at start, as today). Stamp `user_version = 15`. COMMIT.
  2. **Outside any transaction**, still inside open before the writer serves jobs: for each pending instance, under its `config.toml.lock`, idempotently write `budget.breach_action = "pause"` at the instance layer (skip — and keep — when the key appeared meanwhile: an explicit value outranks the marker anyway, and the config-write path clears the row). A missing or unwritable config leaves the row with `config_written = 0`.
  3. **Transaction B** (one writer job): set `done_at`/`config_written` on every row, emit ONE `BreachDefaultUpgraded` event listing each instance and whether its config was written, clear the pending state. COMMIT.
  **Fail-closed across the whole window:** resolution treats ANY `breach_default_upgrade` row as rule (3): explicit key → that; else row → `pause`. So a crash after A, mid-2, or before B can never leave an upgraded instance on `warn` — the pending list is the marker until B finalizes it. Resume on the next writer open: rows without `done_at` re-run stage 2 (idempotent) then B. The event fires exactly once (only B emits it; B runs once because it clears itself). Cross-process: an embedder's second engine serializes on `BEGIN IMMEDIATE` for A/B and the per-home config lock for the writes; `host.lock` already excludes a second host. The marker (the row) renders the note in the Fleet listing and on the instance's Runs until `budget.breach_action` is set explicitly on the instance (that write deletes the row); a hand-edited kind-layer key outranks the row for the value but leaves the note until any explicit instance-layer set (documented edge).
- **Schema v15 shapes.** `policies (name TEXT PRIMARY KEY, selector TEXT, tokens_per_run INTEGER, tokens_cumulative INTEGER, dollars_per_run_micros INTEGER, dollars_cumulative_micros INTEGER, breach_action TEXT, scent_check TEXT NOT NULL DEFAULT 'off', rate_input_micros INTEGER, rate_output_micros INTEGER, rate_cached_micros INTEGER, created_at TEXT, updated_at TEXT)` (`selector` NULL only on `default`); `policy_rates (policy TEXT REFERENCES policies ON DELETE CASCADE, model TEXT, input_micros_per_1m INTEGER, output_micros_per_1m INTEGER, cached_micros_per_1m INTEGER, PRIMARY KEY (policy, model))`; `run_policy (run_id TEXT PRIMARY KEY REFERENCES runs ON DELETE CASCADE, tokens_per_run INTEGER, tokens_cumulative INTEGER, dollars_per_run_micros INTEGER, dollars_cumulative_micros INTEGER, action TEXT, effective_action TEXT, scent_check TEXT, rate_input_micros INTEGER, rate_output_micros INTEGER, rate_cached_micros INTEGER, sources TEXT NOT NULL, updated_at TEXT NOT NULL)`; `breach_default_upgrade (instance_id INTEGER PRIMARY KEY REFERENCES agent_instances ON DELETE CASCADE, config_written INTEGER NOT NULL DEFAULT 0, listed_at TEXT NOT NULL, done_at TEXT)`. Policy names: `^[a-z0-9][a-z0-9_-]*$`, `default` reserved. One crash-atomic step for A's DDL+seed+pending+stamp (the `migrate_v13`/`v14` pattern); B is a writer job, not part of the version step.
- **Scent-Check in 21-3.** The field exists on every Policy row (`off` | `shadow` | `enforce`, a `ScentCheckMode` enum defined now, resolved by the function with the documented tie order, carried on `run_policy` and surfaces) but create/change REFUSE `shadow`/`enforce` with a typed `scent-unavailable` error naming that Scent-Check Modes land with their own story — an accepted-but-inert `enforce` would be the silent lie AI-18 forbids. The default seeds `off`; 22.3 lifts the refusal, decides Q9's environments and never overwrites an edited default.
- **Events (AD-14).** `EngineEvent::Policy(PolicyEvent)`: `{schema_version: 1, kind ∈ created|changed|deleted, name, selector?, limits (after), prior_limits?, rates?, matched, fallbacks, at}` — committed with the outbox row in the change's own job, published after commit. `EngineEvent::BreachDefaultUpgraded(BreachDefaultUpgradedEvent)`: `{schema_version: 1, instances: [{name, config_written}], at}`. Both are new variants on the public exhaustive `EngineEvent` (the 19-2 semver precedent — see Version). SSE and export carry them; the OTLP v1 exporter ignores them (no instance, no run id — the AD-21 interim).
- **The snapshot.** `RunEntry` gains `policy: RunPolicyEntry` (the effective limits, sources, `effective_action`, rate): the writer publishes it on every re-resolve path, so the data path (23.1's proxy) never re-implements resolution (AD-25). Still copy-on-write per 21-2 (O(open Runs) per publish; 24.4 owns the scale work).
- **`hekma policy` CLI** (top-level noun, the naming row). `hekma policy list [--json]`; `hekma policy show <name> [--json]`; `hekma policy create <name> --selector <sel> [--tokens-per-run N] [--tokens-cumulative N] [--dollars-per-run $X] [--dollars-cumulative $X] [--breach-action <warn|pause|stop|block>] [--rate-input $X] [--rate-output $X] [--rate-cached $X] [--dry-run] [--json]`; `hekma policy change <name> [the same limit flags] [--clear <limit>[,<limit>]] [--dry-run] [--json]` — on `default`, `--rate-for <model>` with the `--rate-input/--rate-output/--rate-cached` triple edits the table and `--clear rate:<model>` removes an entry; `hekma policy delete <name> [--dry-run] [--json]`.
