## Intent

**Problem:** The first production Host enforces money at its own external choke point (D4's premise) and wants Hekma's budget/cost decision rules there, provably (FR-44, D5). Today those semantics live only in Rust code and Rust tests: a non-Rust Host cannot pin them, cannot prove its guard matches the engine, and cannot see a semantic change coming.

**Approach:** Publish the decision semantics as a portable artifact. Extract the decision half of the enforcement path into ONE pure core (`governance::decide` — token-then-dollar, per-scope latch, the exact rule `enforce_budget` applies today) and refactor the supervisor to route through it, behavior-identical. From that core plus the pure cost derivations, generate versioned, checksummed JSON vectors — ledger state and ceilings in, decisions out — covering D5's seven rules. The artifact ships inside the crate (`include_str!`), in-repo, on the release surface, and through `kt agent governance-vectors`. CI regenerates it from the engine's own evaluators and byte-compares, so evaluator↔artifact drift is a red build. Small, and first: 19-2..19-5 build on the shared core, and an external Host consumer waits on this story.

## Design Notes

- **One decision core, two consumers.** The vectors must verify the REAL path, not a re-statement of it. Extracting `decide()` out of `enforce_budget` makes the artifact and the engine share one implementation, so evaluator↔artifact drift is impossible rather than merely tested. Rejected: vectors replaying only the two evaluators (would leave latch/ordering uncovered — half of D5's list) and a standalone re-implementation for JSON (drift by construction).
- **Latch/re-arm in v1.** The latch is per-Run, keyed `(dimension, scope)`; its v1 re-arm is the Run boundary (fresh latch, same totals → fires again — the adoption/reaper seeding semantics ride this unchanged). The AD-7 amendment's ceiling-raise re-arm lands with 19-3 and EXTENDS the vectors additively (a minor bump of `vectors_version`; the policy is in docs/governance.md so the extension is already contracted).
- **No-retro-repricing at the vector level.** The store prices each row at its own persisted rate (sqlite.rs:2979-3090 pins); the derivation cases state the same rule purely: rows carrying different rates sum per-row (via `cost_micros_with_cached`), and the case's expected output differs from the total-tokens-at-latest-rate anti-value — a Host implementing the vectors cannot accidentally reprice.
- **Determinism.** The generator is the artifact's only writer: serde struct serialization (declaration order), no maps in the schema where a struct can carry the field, fixed case order, one trailing newline. Byte-compare is therefore stable across platforms and runs.
- **Checksum scope.** SHA-256 over the canonical file bytes only (the `.sha256` file carries it; the in-crate consts carry it; the CLI prints it). The 17-4 module is already FIPS-180-4 test-vector-pinned — no new dependency, and the money-code posture is unchanged (the checksum protects transport, not a money computation).
- **Location.** Inside `crates/hekma-engine/governance/` (not a repo-root dir) because `cargo package` includes only crate-dir files — the crate itself is a publication channel, and a second copy elsewhere would drift. `docs/governance.md` names the canonical path; the release job copies the same file to release assets.
- **Money-code posture.** This story publishes EXISTING semantics read-only: no enforcement behavior, threshold, or rounding changes. It still carries the epic's AI-55 two-pass review because it is the foundation the Host's money guard will be built on.
- **Naming.** `hekma-governance-vectors` everywhere (artifact id, doc title, CLI verb `governance-vectors`). The word "conformance" stays with the TCK (hekma-conformance) — this artifact is about decision semantics, not agent conformance.
