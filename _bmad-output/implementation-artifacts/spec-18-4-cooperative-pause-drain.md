## Intent

**Problem:** Pause today is an OS signal or nothing: `[capabilities.pause]` dispatches SIGSTOP (guaranteed), a transition with a qualifier (best-effort), or fails fast (unsupported). A service agent that could pause COOPERATIVELY — stop accepting new work, finish what is in flight, stay alive to answer probes — cannot express it: a SIGSTOP'd process can finish nothing, answer no ACP, heartbeat no liveness signal. And stop has no in-flight-work wait at all: `kt agent stop` interrupts whatever is running (epics.md Epic 18 preamble; AD-15's reserved drain composite).

**Approach:** Two halves, one contract minor (the open v1.1.0). (1) **Cooperative pause commands**: the `[lifecycle]` block's `pause`/`resume` op templates — legal schema since v1.0.0, declared-but-never-executed seeds — become EXECUTED. When `[lifecycle.pause]` is declared, `kt agent pause` RUNS the declared command (bounded) and records `running → paused` with the new cause `TransitionCause::PauseCooperative`; `kt agent resume` runs `[lifecycle.resume]` and records `paused → running` with `ResumeCooperative`. The declared command OUTRANKS the OS-signal path (a suspended process cannot do what a cooperative pause exists to do), and is OS-INDEPENDENT (it works even where the signal capability is `unsupported`). A cooperative pause is inherently best-effort-class — the engine cannot verify the agent stopped new work — and the cooperative cause IS that honesty, never a plain command cause that would read as a real suspension. (2) **The drain verb**: `kt agent drain NAME` composes AD-15's composite — stop new work (the pause command, if declared) → wait for idle, bounded → stop. A new OPTIONAL `[drain]` manifest section (the story's only new schema) declares the bounded wait: `timeout_ms` (required) and an optional `idle_file` (the agent touches it when in-flight work reaches zero). The outcome — `completed` versus `timed_out` — is DURABLE (`TransitionCause::DrainStopped { completed, waited_ms }` on the terminal stop), and a timed-out drain STILL stops (the composite's last step is unconditional — graceful degradation, surfaced). NO new lifecycle state (AD-15): during the wait the instance reads `paused`; then the existing stop ladder drives `stopping → stopped`.

## Design Notes

- **Executing existing schema beats a new section.** `[lifecycle.pause]/[lifecycle.resume]` have been legal (optional seeds, "1-4's executor will consume") since the contract's first day — 18-4 executes them. Only `[drain]` is new schema (it needs fields the templates cannot carry). Net contract surface: one new section + two validation rules + execution semantics — the lightest shape the letter allows.
- **Cooperative-first, and OS-independent.** A declared command outranks the signal path because the signal path CANNOT provide what the cooperative pause exists for: a SIGSTOP'd gateway finishes nothing, answers no probe. The command path also works where the capability table says `unsupported` (no signal needed) — the capability table governs ONLY the signal path. The pair rule (pause requires resume) closes the unresumable trap at registration, where every other bad manifest dies.
- **The cause IS the honesty.** The epic's "still surfaced as best-effort when it only stops new work" is a statement about VERIFIABILITY, not failure handling: the engine cannot prove the agent stopped new work, so the cause is a distinct cooperative variant — never `PauseBestEffort` (signal-flavored) and never a plain `Command` (would read as guaranteed suspension). Command FAILURE is different and fails loudly: the request itself did not succeed, so the transition rejects and nothing persists.
- **The drain bound's three tiers.** CLI `--timeout-ms` > `[drain].timeout_ms` > the 30 s default (when a pause command exists but no section). The standalone pause cap (30 s) is a DIFFERENT bound: a bare `pause` verb should not hang a CLI for minutes; a drain's wait may legitimately span in-flight work, so the drain bound governs the command there. Two named engine-owned constants, both documented.
- **`idle_file` freshness, not existence.** The idle signal mirrors `file_fresh` semantics (18-1's evaluator family — reuse the shared `probe_kinds::file_fresh` with the wait-bound as the age window, or a small engine-owned slack): a file touched once at startup then never again must not read as idle forever. A declared-but-absent idle file = not idle yet (absent ≡ stale — 18-2's precedent).
- **Timed-out still stops — the letter is unconditional.** "stop new work → wait, bounded → stop": the last step is not conditional. A timed-out drain has already stopped new work; leaving the instance paused-but-running forever would be the silent degradation the house gate forbids. The outcome distinguishes; the stop guarantees.
- **No new state, and the neighbors already cooperate.** A drain-waiting instance reads `paused`, so 18-2's liveness skip covers it (a quiet signal during drain cannot fail the instance — pinned for the cooperative flavor), and 18-3's exactly-`running` classification gate means a coded exit mid-drain takes the plain crash path (documented). The ladder's paused-resume step is the ONE place the composite touches existing stop behavior — and only to make a diagnostic stop lying.
- **Degenerate drain is per-letter, not an error.** "(the pause command, if declared)" makes every step conditional but the last. An agent with no cooperative surface still answers `drain` — with a stop, a completed outcome, and a note that nothing was declared to wait for. Refusing would strand the verb on plain agents for no contract benefit.
- **Naming.** `PauseCooperative`/`ResumeCooperative`/`DrainStopped` variants; `[drain]` section; `PAUSE_COMMAND_CAP` + the drain bound constants beside the other engine-owned cadences. The three existing senses of "drain" (host shutdown ladder in hekma-host, observed-queue drain in the reaper, stdio drain) are untouched — docs/manifest.md + commands.md state the split explicitly (the epic context's binding note).

  5. **Control-API refused-drain class completed during e2e.** The route e2e exposed `DrainRefused` falling into the host's 500 catch-all; the mapping now joins the existing state-conflict 409 arm (drain's running-only gate is the same refused-verb class as `NotRunning`), and `DrainBoundInvalid` maps to the 400 invalid-body class (unreachable through the route, which pre-validates, and the CLI's clap range — mapped for class honesty on any future programmatic surface). docs/control-api.md's drain row states the 409.
