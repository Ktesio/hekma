## Intent

**Problem:** 24-1 moved every supervised process into its own Shim and made a crash leave the process alive on both OSes — but it deliberately kept today's adopt-and-continue semantics for every crash, because the mode-dependent rule does not exist: with Handoff Mode off, FR-55/NFR-1/NFR-9 require orphaned processes to be **cleaned up** and their Runs **ended with the cause** (NFR-9's fifth clause), and nothing implements that; with Handoff Mode on they must be **adopted**, and nothing keys the difference on anything durable — the dead host's mode dies with it. The crash halves that 24-2 explicitly left here are unbuilt: nobody has proved that holds, Leases and Run records survive a `kill -9` within the flush bound (23-2 and 23-4 made them durable rows; the recovery drill never ran), that open calls close as `crash` on the next start across every mode (23-1 built the closure for its own scenarios only), or that in-flight calls fail retryably with the record landing on the Run. The registry-completeness reconcile has known holes: a host killed mid-probe-wait leaves a `starting` row the open path never classifies (an 18-1 review finding, never triggered), a lost Shim's Run has no recovery matrix (24-1 hands it here), and nothing asserts that after a crash the whole estate — Runs, claims, holds, Leases, latches, dispositions, tokens, open calls — reconciles to one truth with no phantom rows. And SM-7 ("no Run stopped, paused or blocked by anything NFR-9 does not list") is a sentence, not a suite: 24-2 proved only its in-place-upgrade arm as flip evidence.

**Approach:** Make the crash the best-understood event in the system. A durable **host posture row** (state.db) records the data-path owner's engine fingerprint and effective Handoff Mode at start, before it serves; the next open's reconcile reads the *dead* owner's posture and keys the split on it — Handoff on → reattach through 24-1's adopt path; off → the ordinary stop ladder per orphaned Run (the one stop NFR-9's fifth clause authorizes), each Run ended with the new cause `engine-crash`, its tokens revoked, the Operator told by name; posture unknown (pre-24-3 directory, an embedder that wrote none) → adopt, never clean up — the conservative arm, because cleanup without a recorded off-posture would be the unrequested stop NFR-9 exists to prevent. The reconcile grows the missing arms: the mid-probe-wait `starting` row classifies honestly, a lost Shim's Run degrades (`supervised-degraded`) or relaunches under a fresh Shim per OS truth, and a one-page **completeness invariant** (R1–R8, Design Notes) is asserted by the drill itself. The **kill -9 drill matrix** kills a real Service Host — SIGKILL on Unix, `taskkill /F` on Windows — with a held call parked at the proxy, calls in flight, Leases, holds and Run records live, at every Control Depth, in both modes, and proves: everything committed before the kill survives exactly; the only loss is unacked usage inside the writer's batch bound (an under-count surfaced as `crash` records, never a double count); revocations stay revoked (R1.6); adoption changes no credential (R1.9); hold and fence reasons republish before the first accept; open calls close exactly once. **SM-7's suite** becomes concrete: an event-cursor auditor plus SDK-shaped harness clients (`wire` and `announced`) that pull every stop/pause/block-class change in the suite's window from the durable export view and map each to one of NFR-9's five clauses — any unmapped action fails the suite naming the event — across seven scenarios (SIGTERM both modes, in-place upgrade, socket-activated restart, `kill -9` both modes, Shim death), asserting zero refused connections only where SM-7 demands it (upgrade, socket-activated) and that every call a restart or crash fails is a recorded retryable error, measured client-side.

## Design Notes

- **What this story owns, and the rulings it builds on.** FR-55 fixes the crash consequences: the kill -9 bullet (the hold record survives; held and in-flight calls end with a retryable error to the client, recorded on the Run as ended by the crash once the host restarts) and the flush-bound bullet (Run records, budgets, Leases and holds survive within FR-10's flush bound, at every Control Depth, whatever the mode). NFR-1 fixes the split (adopt when Handoff is on; clean up only when off); NFR-9 fixes the closed five-clause stop list — cleanup-with-handoff-off is clause 5, and *nothing else a crash does may stop, pause or block anything*. AD-26 fixes the wire facts (a crash refuses connections until the next bind; in-flight calls fail retryably; open `open_calls` close as `crash` at the next start). AD-27 fixes the bound (the 250 ms / 512-event batch; acked writes flush at once). 23-1 built the open-calls closure; 23-2 built durable Leases and the resuming sweeper; 23-4 built durable hold rows, `hold_end: crash` and the first-snapshot-before-accept rule; 24-1 built the Shims, the claim, reconnecting adoption and the `shim-lost` degradation; 24-2 built Handoff Mode on and off, the writer flush and the service-manager checks. This story assembles those halves into one proven matrix and closes the three holes only it can: the mode key (the posture row), the cleanup arm, and SM-7's suite. What it deliberately does NOT own: bypass detection (22-4), scale and compaction (24.4), telemetry (24.5), the Hub (Epic 25), the graceful halves (24-2), any new wire row.
- **Why a posture row, and why the dead host's mode governs.** The reconcile cannot ask a SIGKILLed host which mode it ran; guessing is an NFR-9 hazard in both directions (cleaning up after a handoff-on host kills what the Operator asked to survive; adopting after a handoff-off host leaves orphans running unsupervised forever). The durable answer is one row written at open, before the owner serves — the same write-ahead discipline as AD-5's spawn records. The dead owner's mode is the only honest key because NFR-9 authorizes cleanup "with Handoff Mode off", a property of the host that owned the processes, not of the recoverer. Unknown → adopt: the conservative arm is the only one that cannot manufacture an unrequested stop, and the population of unknown postures shrinks to zero as pre-24-3 directories age out. `control.json` was rejected as the carrier — it is a discovery document the graceful path deletes, and an embedder writes none.
- **Cleanup is an ordinary stop, once per Run.** The clause-5 authorization is to *clean up orphaned processes*, not to invent a new teardown: the reconcile drives the same stop ladder an operator `stop` drives (graceful request, escalation, no surviving process — FR-6), per Run, through the Shim's stop RPC where one exists, and the ordinary events land (transition, `ended`, credential revocations). A group-level kill or a Shim-side teardown would be a second, unaudited stop semantics — exactly what SM-7's suite exists to catch. Pre-v22 direct records: Unix direct orphans take the direct ladder; Windows ones died with the Job and reconcile as ended with the cause. In-process children outlive (AD-25); their tokens are their own.
- **The completeness invariant (R1–R8), asserted by the drill, not by inspection.** After a `kill -9` and the next start's reconcile, for the dead owner's entire estate: **R1** every `open_calls` row closed exactly once (`crash`/`recovered`), no duplicate usage rows, idempotent across a second restart; **R2** every hold reason, Lease, latch, disposition, bound label, explicit limit, token hash, binding and identity row committed before the kill is present and identical after; **R3** no Run whose process is gone remains in a live status, and no Run whose process survives is ended; **R4** every spawn record reconciles — reattached, cleaned, `start-aborted`, or the honest code-unavailable — and no claim names a dead engine; **R5** revocations stay revoked and generations intact (R1.6/R1.9); **R6** hold and fence reasons republish before the first accept; **R7** the sweeper resumes from durable state with no re-issued events; **R8** the posture row names the new owner. The invariant is the story's name ("registry completeness") made checkable; the drill fails loudly on any violation.
- **What the flush bound means here, and what is inside it.** The 2026-10-30 reconcile note (#13) asked for FR-10's ≤5 s loss bound to be stated for crash recovery; the build does better than the placeholder: everything a verb or the pipeline commits is durable before the caller is answered (AD-25/AD-27), so the governance estate has **no** loss window; the only window is the writer's unacked stream — proxied-call records and drained usage inside the final 250 ms / 512-event batch — which surfaces as `crash`-closed records with unknown tokens: an **under-count, never a double count** (the (run, call id) dedup makes replay safe). Parked held calls are connections, not rows (23-4's wording): their bytes die with the process, their records close `crash`, their retries re-hold. The docs state the number the build actually guarantees (Ask First O1 owns whether FR-10's placeholder is also re-worded — a PRD edit that is Islam's).
- **The wire shape of "fails retryably" (Ask First O4).** FR-55 says a held or in-flight call "ends with a retryable error"; a SIGKILLed process cannot send one. The honest reading (the review rubric's own fix, and AD-26's wording): the *connection ends* — an SDK-default-retryable transport error, which is what retryability means on the wire — and the *recorded* half lands at the next start (`crash` closure, `hold_end: crash`, the `Recovery` counts). `proxy-wire v1` documents this as the crash contract; the typed retryable rows (`503 hekma_hold_interrupted`, `hekma_hold_full`, `hekma_ledger_unavailable`, `hekma_run_unavailable`) belong to the paths that can still speak — graceful stops and bounds. The suite's client harness is the measurement instrument SM-7 names ("measured client-side for `wire` and `announced` Runs").
- **SM-7's suite is an audit over durable truth, not instrumentation.** Every stop/pause/block already lands in a durable event family (transitions, run status/ended, dispositions, breaches, `shim`, `handoff`); the auditor reads the export view by cursor (AD-14) and maps causes onto NFR-9's clauses with one table — the same data-driven discipline as AD-15's transition table. The mapping's non-obvious cells: a breach-`pause` latched hold maps to clause 2 (a configured non-`warn` action); an FR-7 qualified pause and an operator `hold` map to clause 1 (a verb); a Shim released by a Handoff SIGTERM maps to clause 4's absence — a release stops nothing, which is the point; cleanup maps to clause 5. Zero-refused-connections is asserted **only** where SM-7 says it (in-place upgrade, socket-activated restart); a crash legitimately refuses until the next bind and the suite asserts those refusals are *retryable*, not absent. The suite re-runs 24-2's arms (they were that story's flip evidence) so SM-7 has one home.
- **The mid-probe-wait arm, absorbed.** The 18-1 review's deferred finding (a host killed mid-probe-wait leaves `starting` + a live process the open path never classifies) never fired by trigger, but it is this story's territory: the open-time reconcile is exactly where crash classification lives. The arm: a `starting` row with a live process and a declared probe re-runs the probe's verdict honestly (bounded by the declared `timeout_ms` from the row's `started_at`); dead probe → `failed` under the Restart Policy; live gate → adopted with the note. Never "as if no gate was declared".
- **Shim death, and what does NOT happen.** AD-23's rule set already fixes the posture (the Shim never relaunches, never writes state.db; the engine applies the Restart Policy at reattach — the adversary review's F12 fix, in the spine). This story completes the matrix 24-1 deferred: the degradation is honest (`supervised-degraded`, stdin refused, raw log), the relaunch is the engine's (new Shim, record first, new Run Key generation per 22-1's per-launch rule), and nothing kills anything on loss — the report-never-kill rule applied to the engine's own supervision. The linger constants stay as 24-1 ruled them; the docs name them.
- **Threats considered** (review ids where they exist; N-ids are this story's):
  - cleanup firing after a handoff-on crash (the unrequested stop) [N1] → the dead owner's recorded posture gates the arm; unknown → adopt; a test seam forces each posture;
  - a stale posture row naming a reused pid [N2] → the fingerprint is pid + start-time (the AD-5 pattern), never pid alone;
  - two engines reconciling one estate [N3] → the posture row is single-row under the writer; the claim CAS and the live-owner gate arbitrate as today; only the data-path owner reconciles the estate (a read-only engine never does);
  - the reconcile itself stopping something mid-classification [N4] → cleanup runs per Run after classification, through the ladder, with the ordinary events; no batch kill;
  - a crash between the posture stamp and the first accept [N5] → the row already names the owner and mode; the next open reconciles it (write-ahead, same as AD-5);
  - usage double-counted by a retry after the crash [N6, 23-1's N8] → (run, call id) dedup; the drill asserts no duplicates;
  - the under-count hidden [N7] → `crash` records with unknown tokens are the surfaced form (AI-18); the docs say what was possibly lost and how it shows;
  - tokens or secrets in the new events/notices [T1.4, R1.15] → token ids only; the sentinel scan covers the drill;
  - the suite green-washing an unauthorized stop [N8] → the auditor reads the durable export view (committed truth), not the bus's at-most-once crash window (the bus deferral stands, unchanged); the table's unmapped cell fails naming the event id.

- 2026-11-14 — **phase 4 built** (stacked on phase 3, #428): T6, SM-7's auditor and its scenarios.
  - **The auditor.** `hekma_conformance::sm7` reads the outbox in `state.db` and maps every initiating stop-, pause- or block-class action onto NFR-9's clauses. Unmapped actions are reported by sequence number and name:
    - `→ stopping` and `running → paused`, by cause;
    - a `starting → failed` readiness timeout;
    - `hold` and `reject` dispositions;
    - non-`warn` breaches.

    Consequence edges are ignored.
  - **The cause table** is pinned by unit tests. A verb and a Handoff-off shutdown share the `stop` command on the wire, so they are one clause.
  - **Scenarios asserting it, with the exact actions taken:**
    - SIGTERM with Handoff on (none) and off (the shutdown's stop);
    - the in-place upgrade (none);
    - `kill -9` with Handoff off (the cleanup), on (none) and unchosen (none);
    - Shim death (none).
  - **Drift:**
    - No socket-activated restart scenario: Hekma has no socket activation yet.
    - No SDK-shaped `wire`/`announced` client harness measuring retryable errors client-side. The upgrade's zero-refused-connections poller is the client-side measure that exists.
    - The suite is the existing tests, not a separate `sm7_no_unrequested_stops.rs` file.
    - It runs on every PR wherever those tests run (O3), but they run only on Unix, since the Shim is Unix-only.

- 2026-11-14 — **phase 6 built** (stacked on phase 5, #430): parked calls across a `kill -9`. The drill now parks a call on the held Run, SIGKILLs the host, and checks O4's crash contract (the client gets no bytes; the connection just ends). It also checks R1: one record at the next start, `outcome: crash`, `disposition: hold`, `hold_end: crash`, `status_class: transport-error`.
  - **Two real bugs, both fixed:**
    - **(1)** The crash closure hard-coded `pass` with no `hold_end`, because `open_calls` never learned a call had parked. The calls store's schema 3 adds `open_calls.held_at` (one crash-atomic ALTER, stamped with it). The proxy marks a call held when it parks (`RecordPump::mark_held`, unacked and best effort like the call start), and the closure writes `hold` and `crash`.
    - **(2)** The per-call record's `outcome`, `disposition` and `status_class` serialized as Rust variant names (`"Crash"`, `"Pass"`, `"TransportError"`) in `hekma calls list --json` and `/v0/calls`, against the documented `crash` / `pass` / `transport-error`. The enums now carry kebab-case (and `2xx`…`5xx`) serde names; `Other(raw)` stays raw.
  - **Drift:** a held mark is not carried when an open call moves to the next day's file at rotation (rare: a call parked across UTC midnight); such a call closes as `pass`.
